# ADR-0001: архитектура сервиса записи к психологу

## Контекст

Психологу нужен помощник-регистратор. Основные пользователи — действующие клиенты: узнать время сессии, перенести или отменить её, задать вопрос о домашнем задании. Второй поток — новые клиенты, которые записываются на первичную консультацию. Сервис определяет, нарушает ли отмена или перенос правила, и при нарушении сообщает клиенту о необходимости оплаты до 100% стоимости сессии.

Исходные условия от владельца:

1. Психолог один.
2. Сервис строится на ядре [platform](https://github.com/apocarteres/platform): Java 21, Spring Boot, Spring Modulith, Angular.
3. Сервис не выставляет счетов и не принимает платежей. Клиент платит психологу напрямую, психолог отмечает оплату в кабинете, бот видит отметку.
4. Календарь собственный. Кабинет и бот читают одни данные.
5. Клиент записывается на любое свободное время внутри расписания, которое задаёт психолог.
6. Кабинет психолога — Angular-приложение на домене психолога.
7. Mini App в Telegram согласован. Виджет на сайте психолога ожидается позже.

## Решение

### Форма

Одна служба на Spring Boot (модульный монолит на Spring Modulith) и два клиента на Angular:

- **кабинет психолога** — на домене психолога, вход через `platform-auth`;
- **Mini App** — выбор слота, анкета первичной консультации, согласие на обработку данных. Та же сборка позже встраивается на сайт как виджет.

Бот не выделяется в отдельный процесс: это адаптер канала внутри службы.

```
Telegram ──webhook──► telegram ─┐
Mini App ──initData─► miniapp ──┼──► booking ──► schedule
Кабинет ───session──► cabinet ──┘       │
                                         ├──► policy   (чистая функция решения)
                                         ├──► billing  (штрафы и отметки оплаты)
                                         ├──► clients  (карточки, приглашения, согласия)
                                         └──► questions (вопросы психологу)
                                  события ──► telegram (исходящие сообщения)
                                           ──► platform-notifications (колокольчик кабинета)
```

### Модули

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `schedule` | Недельное расписание, исключения, типы сессий, расчёт свободных слотов | — |
| `clients` | Карточка клиента, приглашения, привязка Telegram, согласия, удаление по запросу | — |
| `policy` | Версии политики отмен, решение по отмене и переносу | — |
| `booking` | Запись, перенос, отмена, закрытие сессии, неявка | `schedule`, `clients`, `policy` |
| `billing` | Штрафы, отметка оплаты, прощение, долги клиента | `booking` (события) |
| `questions` | Вопросы клиента психологу и ответы, защитная эскалация | `clients` |
| `telegram` | Входящий webhook, сценарии бота, исходящие сообщения | прикладные команды модулей выше |
| `miniapp` | Точки для Mini App и проверка `initData` | прикладные команды модулей выше |

Граф связей ациклический (`REQ-JAVA-MODULES` ядра). Адаптеры каналов (`telegram`, `miniapp`, контроллеры кабинета) вызывают **те же прикладные команды**, бизнес-логика в каналах не дублируется. Будущий LLM-слой и виджет на сайте станут ещё одним адаптером над теми же командами.

### Что берётся из ядра

| Потребность | Ядро |
|---|---|
| Вход психолога, роль `PSYCHOLOGIST`, закрытая регистрация | `platform-auth` (`REQ-AUTH-002`, `REQ-AUTH-016`) |
| Часы в правилах и тестах границ | `platform-time`, `Clock` и `MutableClock` |
| Доступ к данным без ORM, условная запись | `platform-persistence` |
| Контракт ошибок | `platform-web-errors`, `ProblemDetail` |
| Ограничение частоты для webhook и Mini App | `platform-rate-limit` |
| Колокольчик кабинета | `platform-notifications` |
| Однократный запуск периодических команд | `JobLock` из `platform-persistence` |
| Клиент Angular | `@apocarteres/auth`, `http`, `modal`, `action`, `notifications` |

### Решения по частностям

1. **Детерминированное ядро.** Запись, расчёт слотов и решение о штрафе — обычный код с тестами. Язык модели денежных решений не принимает ([ADR-0004](ADR-0004-cancellation-policy-and-charges.md)).
2. **Webhook, а не long polling.** Входящие обновления приходят HTTPS-запросом с секретным заголовком ([ADR-0002](ADR-0002-telegram-client-authentication.md)). Служба не держит постоянного соединения с Telegram и масштабируется как обычный HTTP-сервис.
3. **Свой тонкий клиент Bot API** на Spring `RestClient`: нужны около десяти методов (`sendMessage`, `editMessageText`, `answerCallbackQuery`, `setWebhook`, `setChatMenuButton` и подобные). Отдельная библиотека добавит зависимость, её версию и её модель потоков без выигрыша. Решение пересматривается, если набор методов вырастет.
4. **Периодические операции — команды проекта.** Ядро не запускает фоновую работу само. Напоминания, закрытие прошедших сессий и очистка просроченных приглашений — явные команды. Их вызывает `@Scheduled` проекта под `JobLock`, чтобы при двух экземплярах службы команда выполнялась один раз.
5. **Уведомления психологу** идут в колокольчик кабинета, а по настройке дублируются сообщением бота в личный чат психолога.

## Вне MVP

- **Языковая модель** для свободного текста («перенесите четверг на пятницу вечером»). Будет адаптером, который превращает текст в вызов тех же команд с подтверждением клиентом. Ограничения — в [ADR-0005](ADR-0005-personal-data.md).
- **Виджет на сайте** — сборка Mini App в `iframe` с другим способом входа ([ADR-0002](ADR-0002-telegram-client-authentication.md), вопрос 2).
- **Экспорт календаря** в личный календарь психолога лентой ICS только для чтения.

## Отклонённые варианты

| Вариант | Почему нет |
|---|---|
| Отдельная служба бота на Python (aiogram) | Второй стек и дублирование домена: правила отмен жили бы в двух местах или бот ходил бы в API за каждым решением. |
| Low-code (n8n и подобные) | Правила отмен с деньгами не покрываются тестами, нет версии политики и аудита. |
| AI-агент как основа | Решение о штрафе недетерминировано и необъяснимо. Ошибка модели — денежный спор с клиентом. |
| Внешний календарь (Google, Яндекс) как источник истины | Внешняя зависимость для основной функции. Данные о сессиях у третьей стороны, для Google — ещё и за рубежом (152-ФЗ, [ADR-0005](ADR-0005-personal-data.md)). Атомарность записи не гарантирована. |
