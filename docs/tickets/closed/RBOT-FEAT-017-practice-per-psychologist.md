# Своя практика у каждого психолога

## Проблема

Клиенты, расписание, типы сессий и записи были общими для всех учётных записей с ролью психолога: каждый психолог видел чужих клиентов.

## Подтверждение

Замечание владельца от 2026-10-01 со снимком «Клиентов»: у каждого психолога своя клиентская база. Решения владельца в тот же день:

- своя у каждого вся практика — клиенты, расписание, типы сессий, записи;
- администратор видит только учётные записи; с ролью психолога у него своя практика;
- уже заведённое на рабочей среде отходит Яне (`RBOT_PRACTICE_OWNER` на хосте, почта в репозиторий не попадает);
- клиент в Telegram может ходить к нескольким психологам и выбирает, к кому записаться.

## Последствия при сохранении текущего поведения

Сведения о клиентах одного психолога видны другому — нарушение конфиденциальности и 152-ФЗ (ADR-0005).

## Требуется

1. Столбец `practitioner_id` (учётная запись психолога) у параметров записи, недели, исключений, типов сессий, клиентов и сессий; запросы кабинета — только по своей практике.
2. Пересечение сессий запрещено внутри практики; у одного аккаунта Telegram — по карточке в каждой практике.
3. Переход: текущие данные — владельцу из `RBOT_PRACTICE_OWNER`, без него — самому раннему психологу без роли администратора.
4. Кабинет: разделы практики — только роли психолога; «Имя для клиентов» в «Правилах записи».
5. Приложение клиента: выбор психолога, если их несколько; имя психолога у записи.

## Критерии приёмки

- `PracticeIsolationIT`: второй психолог не видит типов, клиентов, правил записи первого; не может поставить чужой тип в свой промежуток, изменить чужой тип, выпустить ссылку чужому клиенту; Telegram, привязанный к двум психологам, видит две практики с их именами.
- Интеграционные тесты записи, кабинета и Telegram проходят на практиках.

## Ход работы

- 2026-10-01: переход `rbot:010-practices` (`breaking`, раскат с остановкой): столбцы, шаг `com.yanapaderina.migration.PracticeOwner`, ключи и ограничения; `btree_gist` для исключения по практике. Порты `Availability`, `BusyTime`, `Clients` принимают практику; точки клиента — `/practices`, `offer?practice`, `slots?practice`, `practice` в записи. `/api/cabinet/**` — только роль психолога.
- Клиент по почте (стенд QA) видит всех психологов; карточка в практике заводится при первой записи.
