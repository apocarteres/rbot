# Идентификаторы задач несут префикс проекта

## Проблема

Идентификаторы задач проекта не несут префикса проекта, поэтому совпадают с идентификаторами ядра и других потребителей: одна и та же строка `OPS-020` означает разные задачи в разных репозиториях, и ссылка на неё не указывает ни на одну из них.

## Основание

Обязательство ядра `ticket-prefix`, требование `REQ-NAMING-012`, объявлено в версии ядра 1.4.0. Срок исполнения: 3 выпуск(ов) потребителя.

## Последствия при сохранении текущего поведения

Требование ядра действует, а проект ему не соответствует: расхождение обнаруживается не проверкой, а при следующем изменении в этой области.

## Требуется

1. В настройке проверок объявлен `ticketPrefix` — уникальный префикс проекта из заглавных латинских букв и цифр.
2. Идентификаторы и имена файлов задач переведены на форму `<ПРЕФИКС>-<ОБЛАСТЬ>-<NNN>`.
3. Ссылки на задачи в документах, составах выпусков и сообщениях фиксаций приведены к новым идентификаторам.
4. Ссылки на задачи чужих проектов отделены именем проекта через косую черту (`platform/CORE-API-004`) до запуска миграции: неотделённый идентификатор миграция читает как свой.

## Критерии приёмки

- `conventions check` и `conventions docs-check` проходят после перехода.
- Ни один идентификатор задачи проекта не совпадает с идентификатором задачи ядра.
- В документах не осталось ссылок вида `<ОБЛАСТЬ>-<NNN>` без префикса.
- Ни один идентификатор чужого проекта не получил префикса этого проекта.

## Ход работы

- 2026-09-30: `ticketPrefix` = `RBOT` с 2026-09-30 (MVP-01), задачи проекта — `RBOT-<ОБЛАСТЬ>-<NNN>`, этапы плана — `MVP-<NN>`. Задачи ядра названы отделённо: `platform/CORE-ARC-022`. `conventions check` и `docs-check` проходят.
