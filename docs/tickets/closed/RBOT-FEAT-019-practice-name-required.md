# Без имени для клиентов приглашать нельзя

## Проблема

Экран согласия в приложении показывал «Психолог: Психолог»: у психолога не заполнено «Имя для клиентов», а в учётной записи ядра есть только почта.

## Подтверждение

Замечание владельца от 2026-10-02 со снимком экрана согласия на рабочей среде: в графе «Психолог» нужно имя психолога. Решение владельца в тот же день: имя обязательно — без него приглашение не выпускается.

## Последствия при сохранении текущего поведения

Клиент даёт согласие, не видя, какому психологу (оператору данных, ADR-0005) он его даёт.

## Требуется

1. Выпуск и перевыпуск приглашения отвергаются с кодом `practice-name-missing`, пока в правилах записи не заполнено «Имя для клиентов».
2. «Клиенты»: предупреждение со ссылкой на поле, кнопки приглашения недоступны.

## Критерии приёмки

- `PracticeIsolationIT`: психолог без имени получает `practice-name-missing`, после заполнения имени — ссылку; приложение показывает его имя.

## Ход работы

- 2026-10-02: тикет заведён. Порт `clients.PracticeNames` реализован в `booking` по `Availability.names`: модуль `clients` по-прежнему ни от кого не зависит.
- QA: `admin@` без имени — на «Клиентах» предупреждение со ссылкой `/schedule?tab=settings`, «Пригласить клиента» недоступна. Интеграционных тестов 32, все проходят.
