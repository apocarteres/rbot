# Mini App: выбор слота и первичная консультация

## Проблема

Выбирать время кнопками в чате неудобно, а анкету первичной консультации нельзя собирать сообщениями: данные о здоровье не должны задерживаться в переписке Telegram.

## Подтверждение

Mini App согласован владельцем. Проверка `initData` — [ADR-0002](../../../decisions/ADR-0002-telegram-client-authentication.md), минимизация данных в Telegram — [ADR-0005](../../../decisions/ADR-0005-personal-data.md).

## Последствия при сохранении текущего поведения

Новому клиенту записаться неудобно, а анкета проходила бы через серверы Telegram.

## Требуется

1. Модуль `miniapp`: точки `/miniapp/api/**` в отдельной цепочке; проверка подписи `initData` и `auth_date` не старше 10 минут; ограничение частоты на `telegram_user_id`.
2. Приложение Angular: общий код с кабинетом через пакеты `@apocarteres/*`, тема из `Telegram.WebApp.themeParams`, пояс клиента из браузера.
3. Экран выбора слота: тип сессии → дни → свободное время → подтверждение. Для переноса — тот же экран с предупреждением `evaluate` перед подтверждением.
4. Сценарий нового клиента: согласие (MVP-03) → анкета (имя, контакт, запрос в свободной форме, удобное время) → выбор слота первичной консультации → запись. Анкета хранится шифрованной (ADR-0005).
5. Принятие действующей политики отмен, если клиент её ещё не принял.
6. Сборка не зависит от окружения Telegram так, чтобы позже встроиться на сайт с другим входом (ADR-0002, вопрос 2).

## Критерии приёмки

- Запрос с подделанной или просроченной `initData` → `401`.
- Unit-тест проверки подписи на эталонном примере из документации Telegram.
- Слот, занятый между показом и подтверждением, даёт понятный отказ и обновлённый список.
- Анкета в базе нечитаема без ключа шифрования.
- Ручная проверка в Telegram на iOS, Android и Desktop: тема, кнопка «Назад», закрытие после записи.
