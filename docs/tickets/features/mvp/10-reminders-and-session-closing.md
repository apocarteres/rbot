# Напоминания, закрытие сессий и очистка просроченного

## Проблема

Клиенты забывают о сессиях. Прошедшие сессии остаются `BOOKED`. Просроченные приглашения и токены копятся.

## Подтверждение

[ADR-0001](../../../decisions/ADR-0001-service-architecture.md), решение 4: периодические операции — явные команды, триггер — `@Scheduled` проекта под `JobLock`.

## Последствия при сохранении текущего поведения

Больше неявок и поздних отмен, неверный календарь в кабинете, данные хранятся дольше нужного (ADR-0005).

## Требуется

1. Команда `sendDueReminders(now)`: напоминание за N часов до сессии (N из настроек практики). Отметка «напоминание отправлено» на сессии, повтор не шлётся. Текст — только дата и время (ADR-0005), кнопки «Мои сессии» и «Перенести».
2. Команда `completePastSessions(now)`: `BOOKED`, закончившиеся больше M часов назад, → `COMPLETED`.
3. Команда очистки: просроченные приглашения, токены ядра (`Accounts.purgeTokens`), данные с истёкшим сроком хранения.
4. Триггеры `@Scheduled` под `JobLock`, расписание в настройках службы.

## Критерии приёмки

- Тесты команд на `MutableClock`: напоминание уходит один раз; отменённая сессия напоминания не получает; сессия, перенесённая после отправки, получает новое напоминание.
- Два экземпляра службы при одном срабатывании выполняют команду один раз (интеграционный тест с `JdbcJobLock`).

## Открытые вопросы

**Вопросы:** решены

1. **Когда напоминать.** За сколько часов, одно напоминание или два (например за 48 ч — «последний день бесплатной отмены» и за 3 ч)?
   Ответ 2026-10-01: одно напоминание за 24 ч.
