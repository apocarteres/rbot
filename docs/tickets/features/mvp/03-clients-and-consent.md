# Карточки клиентов, приглашения и согласие

## Проблема

Бот должен отличать действующего клиента от постороннего и не обрабатывать данные о здоровье без согласия.

## Подтверждение

[ADR-0002](../../../decisions/ADR-0002-telegram-client-authentication.md) — привязка по приглашению; [ADR-0005](../../../decisions/ADR-0005-personal-data.md) — отдельное согласие до первых данных.

## Последствия при сохранении текущего поведения

Любой, кто нашёл бота, мог бы получить доступ к чужим сессиям. Обработка без согласия нарушает ст. 10 152-ФЗ.

## Требуется

1. Модуль `clients`: `client` (состояния `PROSPECT`, `ACTIVE`, `ARCHIVED`), `client_invite` (хеш токена, срок, погашение), `consent` (версия текста, мгновение, канал), `consent_text` (версии).
2. Команды: создать клиента, выпустить приглашение (старое гасится), привязать Telegram по токену, принять согласие, отозвать согласие, архивировать, удалить по запросу субъекта (ADR-0005).
3. Экраны кабинета: список клиентов с поиском, карточка, кнопка «Пригласить» с копированием ссылки, статус согласия, удаление с подтверждением в модальном окне.
4. Текст согласия редактируется версиями в кабинете. Новая версия требует повторного принятия.

## Критерии приёмки

- Токен одноразовый: второе использование и просроченный токен отвергаются одинаково, без раскрытия причины.
- В базе хранится только хеш токена.
- Привязка без принятого согласия не даёт клиенту состояния `ACTIVE`.
- Удаление по запросу стирает карточку, согласия и приглашения; тест проверяет, что строк не осталось.
- `telegram_user_id` и имя не попадают в журналы (тест на захват журнала).
