# Готовность к работе: хостинг в РФ, резервные копии, документы 152-ФЗ

## Проблема

Сервис обрабатывает данные о здоровье. Запуск без локализации, резервных копий и документов оператора недопустим.

## Подтверждение

[ADR-0005](../../../decisions/ADR-0005-personal-data.md): локализация (ст. 18 ч. 5), согласие (ст. 10), уведомление Роскомнадзора (ст. 22), договор поручения.

## Последствия при сохранении текущего поведения

Нарушение 152-ФЗ с первого клиента. Потеря данных календаря при сбое сервера.

## Требуется

### Техническая часть

1. Хостинг в РФ: служба, PostgreSQL, Redis, хранилище резервных копий.
2. Развёртывание по требованиям ядра (`REQ-DEPLOYMENT`): коммит как единица, проверка работоспособности, идемпотентность.
3. Резервные копии по `REQ-BACKUPS` ядра: внешнее хранилище в РФ, конечный срок хранения, проверка восстановления.
4. HTTPS для кабинета, webhook и Mini App на домене психолога; регистрация webhook командой из MVP-04.
5. Секреты (токен бота, секрет webhook, ключ шифрования, пароль базы) — только из окружения.
6. Инструкции в `docs/runbooks`: развёртывание, смена токена бота, восстановление из копии.

### Документы (готовит юрист, задача отслеживает наличие)

1. Политика обработки персональных данных на сайте.
2. Текст согласия на обработку данных о здоровье — загружается в кабинет версией (MVP-03).
3. Уведомление Роскомнадзора.
4. Договор поручения психолога с эксплуатантом.
5. Оферта или договор с правилами отмен (ADR-0004, вопрос 5).

## Критерии приёмки

- Восстановление из резервной копии проверено на отдельном стенде, время записано.
- Все пять документов есть; тексты согласия и политики отмен в кабинете совпадают с утверждёнными юристом.
- Внешний сканер не находит открытых портов, кроме HTTPS.
