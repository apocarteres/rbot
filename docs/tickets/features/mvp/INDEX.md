# План MVP: регистратор психолога в Telegram

## Цель

Действующий клиент в Telegram видит свои сессии, переносит и отменяет их по правилам и узнаёт о штрафе до подтверждения. Новый клиент записывается на первичную консультацию. Психолог в кабинете задаёт расписание и политику, видит записи и долги, отмечает оплату и отвечает на вопросы.

Архитектура — [ADR-0001](../../../decisions/ADR-0001-service-architecture.md).

## Текущий объём

Решение владельца 2026-10-01: пока реализуется только работа с расписанием — расписание (MVP-02), запись, перенос и отмена в кабинете и приложении клиента (MVP-05). Разбор того, что пишет клиент, не делается: MVP-12 вне текущего объёма, критерий плана о телефонах помощи до пересмотра не проверяется.

## Вне MVP

- Языковая модель для свободного текста — адаптер над командами MVP ([ADR-0001](../../../decisions/ADR-0001-service-architecture.md), [ADR-0005](../../../decisions/ADR-0005-personal-data.md)).
- Виджет на сайте психолога — сборка Mini App с другим способом входа ([ADR-0002](../../../decisions/ADR-0002-telegram-client-authentication.md)).
- Переход на порт внешней личности ядра — после выпуска порта в platform.
- Экспорт календаря в ICS.

## Критерии приёмки плана

- Все этапы в состоянии `done`.
- Сквозной сценарий на тестовом боте: психолог задаёт расписание и политику → приглашает клиента → клиент привязывается и соглашается → записывается через Mini App → переносит без штрафа → отменяет поздно и видит сумму → психолог отмечает оплату → клиент получает подтверждение.
- Сквозной сценарий нового клиента: `/start` без приглашения или кнопка «Записаться» на сайте → согласие → анкета → запись на первичную консультацию → психолог видит анкету в разделе «Анкеты» и запись.
