# Расписание психолога и свободные слоты

## Проблема

Клиент записывается только внутри расписания психолога, а расписания в системе нет.

## Подтверждение

Требование владельца: психолог задаёт рабочие дни и часы, клиент записывается на любое время в их пределах. Модель — [ADR-0003](../../../decisions/ADR-0003-own-calendar-and-booking.md).

## Последствия при сохранении текущего поведения

Запись (MVP-05) и Mini App (MVP-08) не из чего строить.

## Требуется

1. Модуль `schedule`: таблицы `practice_settings`, `work_schedule`, `schedule_override`, `session_type`.
2. Команды: задать настройки практики, задать интервалы дня недели (несколько за день), добавить и снять исключение даты, создать, изменить и деактивировать тип сессии. Цена — `numeric`, в коде `BigDecimal`.
3. Операция чтения `freeSlots(from, to, sessionType)` по алгоритму ADR-0003. Пока занятых сессий нет, она учитывает порт «занятые интервалы», который реализует MVP-05.
4. Экраны кабинета: недельное расписание, исключения (отпуск диапазоном дат), типы сессий, настройки практики, предпросмотр слотов на две недели.

## Критерии приёмки

- Тесты `freeSlots` на `MutableClock`: `lead_time` отсекает ближайшие слоты; горизонт отсекает дальние; исключение `closed` убирает день; особые часы заменяют шаблон; слот с перерывом, не помещающийся в конец интервала, не выдаётся.
- Тест пояса: шаблон «10:00 Europe/Moscow» даёт мгновение 07:00Z.
- Изменения расписания сразу видны в предпросмотре.

## Открытые вопросы

**Вопросы:** решены

1. **Параметры по умолчанию.** `lead_time`, `horizon`, `slot_step`, `buffer`, длительность и цена первичной и регулярной сессии — [ADR-0003](../../../decisions/ADR-0003-own-calendar-and-booking.md), вопрос 3.
   Ответ 2026-10-01: значения задаёт психолог в кабинете; в первой версии — пустые настройки практики, которые нужно заполнить до открытия записи. Пояс психолога — Europe/Moscow. Типы сессий — три, формат (очно, онлайн) — свойство типа.

## Ход работы

- 2026-10-01: модуль `schedule`: наружу — порт `BusyTime` и `TimeRange` для занятого времени (реализует MVP-05); `internal.data` — DAO по одному оператору (`practice-settings`, `work-interval`, `schedule-day`, `session-type`); `internal.app` — `ScheduleAdministration` (команды с транзакциями), `SlotPreview` и чистый `SlotCalendar`; `internal.web` — `/api/cabinet/schedule/**` для психолога и администратора.
- Переход базы — свой набор Liquibase `rbot:001-schedule` с меткой `additive` (SQL — `db/changelog/sql/`, вне `includeAll`). Типы сессий из анкеты сайта — «Разовая консультация» 90 мин (для нового клиента), «Психотерапия очно» и «Психотерапия онлайн» 60 мин — заведены выключенными с ценой 0: цену и включение задаёт психолог. Параметры записи пусты до заполнения, слоты до этого — `settings-incomplete`. Пояс — Europe/Moscow.
- Отказ на неразобранное тело и неверный параметр запроса — 400 `request-unreadable` и `parameter-rejected` портом `ErrorCodeResolver` (`web.internal.RequestErrorCodes`); раньше они уходили в 500.
- Кабинет: раздел «Расписание» — параметры записи, рабочая неделя с несколькими промежутками в день, отпуск и особые часы, типы сессий, предпросмотр слотов на 14 дней; после каждой правки предпросмотр пересчитывается.
- Проверки: `SlotCalendarTest` (8 случаев: пояс 10:00 МСК → 07:00Z, шаг и перерыв, минимальный срок, горизонт, закрытый день и особые часы, занятое время, незаполненные параметры, пересечение промежутков); `ScheduleIT` на PostgreSQL в сборочном контейнере (4 случая: настройка → слоты → отпуск, типы и проверка полей, отказ 400 на плохой запрос, гость — 401). QA в браузере под `psychologist@yanapaderina.test`: параметры 12 ч / 28 дн / 30 мин / 10 мин, понедельник 10:00–18:00, «Психотерапия очно» 4500 ₽ — предпросмотр показывает понедельники 10:00–16:30.
- 2026-10-01: по решению владельца страница разбита на вкладки по согласованному макету: «Неделя», «Исключения» (со счётчиком предстоящих), «Типы сессий», «Параметры»; выбранная вкладка — в адресе (`?tab=`). Под заголовком — «Запись открыта» со сводкой параметров либо «Запись закрыта» со ссылкой на параметры. Неделя — строка на день с промежутками, правка раскрывается по дню и сохраняет только его. «Как увидит клиент» — постоянная колонка справа, на узком экране — под вкладками.
