# Приложение клиента: мастер записи и мои сессии

## Проблема

В приложении клиента на `bot.yanapaderina.com` только заглушка: записаться, увидеть свои записи и отменить их нельзя. Тестового клиента для QA нет.

## Подтверждение

Запрос владельца от 2026-10-01: завести тестовый аккаунт клиента и делать приложение клиента без языковой модели, пошаговым мастером. Макет согласован в тот же день. Ответы владельца:

- в первую итерацию входят запись и «мои сессии»; новый клиент с анкетой и согласием идёт следующей итерацией;
- запись клиента сразу `BOOKED` (ADR-0003, вопрос 1);
- до политики отмен (MVP-06) клиент отменяет сам без штрафа, не позже минимального срока записи.

## Последствия при сохранении текущего поведения

Сценарий записи не проверить на стенде. Модулю записи (MVP-05) и Mini App (MVP-08) не на чем строиться.

## Требуется

1. Роль `CLIENT`. Вход в приложение клиента по почте и паролю ядра до канала Telegram (MVP-04). Учётная запись QA `client@yanapaderina.test`.
2. Модуль `clients`: карточка `client`, связанная с учётной записью, без имени и контактов. Карточка заводится при первой записи.
3. Модуль `booking`: таблица `session` с ограничением `session_no_overlap` (ADR-0003). Команды клиента `book` и `cancel`, чтение ближайших записей. Реализация порта `BusyTime`: занятое время убирается из слотов, в том числе из предпросмотра кабинета.
4. Открытый порт расписания `Availability`: условия записи, типы сессий, свободное время.
5. Точки `/api/client/**` только для роли `CLIENT`: `offer`, `slots`, `sessions`, `sessions/{id}/cancel`.
6. Приложение: главная со списком записей и отменой в окне; мастер «тип → день → время → проверка → готово». Время показывается в поясе психолога с подписью.

## Критерии приёмки

- 10 одновременных записей на один слот дают ровно одну сессию.
- Занятое время пропадает из слотов, отмена его возвращает.
- Запись вне свободного слота, на выключенный тип и при закрытой записи отвергается кодом.
- Отмена чужой записи — `session-missing`; повторная отмена — `session-not-active`; внутри минимального срока — `cancel-too-late`.
- Психолог не попадает в `/api/client/**`, клиент — в `/api/cabinet/**`.
- На QA: клиент записывается мастером, видит запись на главной и отменяет её.
