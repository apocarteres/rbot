# Сообщение фиксации начинается с идентификатора задачи

## Проблема

Сообщения фиксаций не называют задачу, поэтому состав выпуска и выпущенное состояние ничем не связаны: в выпуск попадает всё, что успело лечь в `main`, и снятие задачи из состава не снимает её работу.

## Основание

Обязательство ядра `commit-ticket-id`, требование `REQ-PROJECT-PROCESS-023`, объявлено в версии ядра 1.6.0. Срок исполнения: 2 выпуск(ов) потребителя.

## Последствия при сохранении текущего поведения

Требование ядра действует, а проект ему не соответствует: расхождение обнаруживается не проверкой, а при следующем изменении в этой области.

## Требуется

1. Сообщение фиксации начинается с идентификатора задачи; коммит, обслуживающий выпуск, несёт строку `Release-cycle: <идентификатор выпуска>`.
2. В настройке проверок объявлен `commitRuleSince` — коммит, с которого правило действует; история до него проверкой не охватывается.
3. Снятие задачи из состава сопровождается отменой её коммитов: отменяющий коммит несёт метку `!revert` сразу после идентификатора задачи.

## Критерии приёмки

- Закрытие выпуска проходит: в диапазоне нет коммитов без задачи и коммитов задач вне состава.
- Снятая из состава задача роняет закрытие, пока её работа не отменена коммитом с меткой `!revert`.
- Правило соблюдается и для коммитов самого цикла выпуска.
