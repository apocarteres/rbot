# Время для записи открывает психолог

## Проблема

Свободное время из рабочих часов, шага и правил записи сразу становилось доступно клиенту. Психолог не мог решить, какое из этого времени отдать клиентам.

## Подтверждение

Просьба психологов, переданная владельцем 2026-10-06: в кабинете виджет с предлагаемым расписанием, где психолог вручную выбирает время, доступное клиенту; по умолчанию всё закрыто, есть «Открыть всё». Решения владельца в тот же день по макету:

- виджет «Время для записи» вместо карточки «Как увидит клиент» в «Расписании»;
- «Открыть всё» — кнопка на показанную неделю, новые недели остаются закрытыми;
- открытое время начала — для всех типов сессий, которые промежуток разрешает и в которые помещается сессия;
- после раската у всех практик всё закрыто.

## Последствия при сохранении текущего поведения

Клиенты записываются на время, которое психолог не готов отдавать.

## Требуется

1. Таблица `open_slot`: практика и мгновение начала. Клиент видит и бронирует только предлагаемое время, которое открыто и не занято; перенос клиентом — тоже только на открытое время.
2. `GET /api/cabinet/schedule/openings?from&to`: предлагаемое время начала по всем включённым типам с состоянием `OPEN`, `CLOSED`, `BUSY`; `PUT` — открыть и закрыть списком.
3. Виджет: неделя со стрелками в пределах горизонта записи; клик по времени — открыть или закрыть, клик по дню — весь день, «Открыть всё на неделе», «Закрыть всё»; занятое время нажать нельзя.
4. Психолог записывает клиента из «Записей» на любое свободное время, открытое или нет.

## Критерии приёмки

- `ClientBookingIT`: пока время не открыто, клиент не видит слотов и не может записаться; после открытия — видит и записывается; закрытое снова пропадает.
- `ClientBookingIT`: виджет отдаёт закрытое, открытое и занятое время; открыть время в прошлом нельзя (`opening-rejected`).

## Ход работы

Клиент по почте видит у «Тестового психолога» только это время; 90-минутная консультация в 16:30 не предлагается — не помещается.
