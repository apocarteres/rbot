# Оповещение, если копия базы не делалась больше суток

## Проблема

Копию базы делает `rbot-backup.timer` раз в сутки (RBOT-OPS-009), но сбой копирования никто не увидит: ни метрики, ни оповещения у копии нет. В RBOT-OPS-020 это правило не вошло.

## Подтверждение

RBOT-OPS-020, п. 4: «копия базы старше 26 часов — `critical` (если копия отдаёт метрику; иначе — отдельной задачей)». `scripts/ops/backup.sh` метрику не отдаёт; `node_exporter` рабочей машины (общий с fileio) запущен без каталога textfile.

## Последствия при сохранении текущего поведения

Копии могут не делаться неделями — это обнаружится только при восстановлении.

## Требуется

1. Мгновение последней успешной копии становится метрикой `rbot_backup_last_success_timestamp_seconds` — способ на выбор: отметка `backup.sh`, которую отдаёт служба, или каталог textfile у `node_exporter` по согласованию с fileio.
2. Правило `RbotBackupStale` в `monitoring/prometheus/rbot-alerts.yml`: копии нет больше 26 часов — `critical`, с тестом `promtool`.
3. Панель «Последняя копия» на дашборде `rbot-service`.

## Критерии приёмки

- Остановленный таймер копий даёт оповещение через 26 часов (проверка — тестом правила и пробой с подменённой отметкой).
