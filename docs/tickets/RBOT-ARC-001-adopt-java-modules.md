# Java-код разделён на модули, граф связей ациклический

## Проблема

Java-код проекта не разделён на модули с объявленными границами, либо граф связей между модулями содержит циклы. Модуль в цикле нельзя собрать, проверить и заменить отдельно: его тест тянет за собой всё кольцо, а косвенный цикл не виден в объявлениях и обнаруживается только обходом графа.

## Основание

Обязательство ядра `java-modules`, требование `REQ-JAVA-MODULES-003`, объявлено в версии ядра 1.9.0. Срок исполнения: 3 выпуск(ов) потребителя.

## Последствия при сохранении текущего поведения

Требование ядра действует, а проект ему не соответствует: расхождение обнаруживается не проверкой, а при следующем изменении в этой области.

## Требуется

1. Java-код разделён на модули: контракты экспортируются корневым пакетом модуля, реализация лежит во внутренних подпакетах и снаружи не используется.
2. Межмодульные зависимости объявлены явно перечнем, а не восстанавливаются чтением импортов.
3. Граф связей модулей ациклический: ни явных, ни косвенных циклов. Найденный цикл снимается выносом общей части в третий модуль или обращением связи портом, а не исключением из правила.
4. Средства, скрывающие цикл, не применяются: отложенное внедрение зависимости и разрешение циклических ссылок настройкой платформы приложений. Запрет проверяется наравне с графом.
5. Структурная проверка графа входит в набор `check`. Штатный путь — готовые правила ядра `platform-arch-rules`; собственная реализация, утверждающая то же самое, равноценна (`REQ-ADOPTION-021`).

## Критерии приёмки

- `check` содержит проверку, которая отказывает при появлении цикла между модулями.
- Проверка отказывает и на косвенном цикле, а не только на прямом: это закреплено отдельным случаем.
- Проверка покрывает и вложенные уровни: подмодули внутри модуля проверяются отдельным случаем.
- Перечень межмодульных зависимостей доступен чтением, без разбора импортов.

- `ArchRulesProbeTest`: косвенный цикл a → b → c → a и цикл подмодулей x ↔ y на образцах в `architecture/fixture` роняют проверку.
