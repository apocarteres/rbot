# Окно с удалённым действием закрывается после успеха, каждая кнопка окна объявляет своё действие

## Проблема

Окна с удалённым действием передают намерение хозяину и закрываются до ответа сервера: отказ приходит вне окна, введённое стирается, двойное нажатие даёт два запроса, признак ожидания ведут руками.

## Основание

Обязательство ядра `modal-actions`, требование `REQ-CLIENT-MODAL-005`, объявлено в версии ядра 3.0.0. Срок исполнения: 3 выпуск(ов) потребителя.

## Последствия при сохранении текущего поведения

Требование ядра действует, а проект ему не соответствует: расхождение обнаруживается не проверкой, а при следующем изменении в этой области.

## Требуется

1. Удалённое действие окна запускает кнопка директивой apcrAction из пакета @apocarteres/action, с обязательным обработчиком отказа [apcrActionFailure] (REQ-CLIENT-ACTION-001).
2. Окно закрывается по событию (apcrActionDone), то есть только после успеха (REQ-CLIENT-MODAL-005).
3. При отказе окно остаётся открытым, введённое сохраняется, отказ показывается средствами проекта (REQ-CLIENT-MODAL-006).
4. Каждая кнопка окна объявляет apcrAction либо apcrLocal (REQ-CLIENT-MODAL-007).
5. Собственный признак ожидания в окнах снят: ожидание ведёт ядро (REQ-CLIENT-ACTION-002).

## Критерии приёмки

- Правило modal-actions в check замечаний не даёт.
- Заведомый отказ сервера оставляет окно открытым с введённым — проверено один раз при принятии.
- Двойное нажатие на кнопку действия даёт один запрос.

## Ход работы

- 2026-09-30: у единственного окна «Страница устарела» удалённого действия нет: кнопка «Обновить страницу» объявлена `apcrLocal`. Правило `modal-actions` замечаний не даёт.
- Заведомый отказ: кнопка окна без `apcrLocal` и `apcrAction` — правило называет её («кнопка в модальном окне не объявляет, удалённое ли у неё действие»); правка возвращена.
- Критерии об отказе сервера и двойном нажатии проверяются на первом окне с удалённым действием: сейчас такого окна нет, ожидание вызова вело бы `apcrAction` ядра.
