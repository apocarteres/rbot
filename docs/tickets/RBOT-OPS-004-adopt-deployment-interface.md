# Развёртывание через интерфейс ядра: среда именем, составляющие объявлены, манифест и сверка развёрнутого

## Проблема

Развёртывание проекта устроено по-своему: свой вход со своими ключами, свой перечень составляющих в коде скрипта, свой манифест сборки. Человек, перешедший между проектами ядра, читает справку заново, а ядро не знает, из чего проект состоит, и потому не может ни предложить шага, ни проверить порядок.

## Основание

Обязательство ядра `deployment-interface`, требование `REQ-DEPLOYMENT-015`, объявлено в версии ядра 1.39.0. Срок исполнения: 3 выпуск(ов) потребителя.

## Последствия при сохранении текущего поведения

Требование ядра действует, а проект ему не соответствует: расхождение обнаруживается не проверкой, а при следующем изменении в этой области.

## Требуется

1. Единственный вход в развёртывание принимает имя среды обязательным доводом; всё прочее по умолчанию — разворачиваются все объявленные составляющие (REQ-DEPLOYMENT-015).
2. Составляющие и среды объявлены разделом deployment в .conventions.json, каждая составляющая называет свой артефакт; скрипт развёртывания спрашивает перечень командой conventions components, а не держит его у себя.
3. Манифест сборки пишется командой conventions manifest: по объявленным составляющим, с контрольными суммами, тегом выпуска или названной причиной его отсутствия (REQ-DEPLOYMENT-002).
4. Развёрнутое сверяется с собранным командой conventions deployed — по метке работающего контейнера либо по установленному файлу (REQ-DEPLOYMENT-016).
5. Проверка работоспособности обращается к самому сервису командой conventions health, а не к тому, что стоит перед ним (REQ-DEPLOYMENT-006).

## Критерии приёмки

- Вход в развёртывание принимает имя среды обязательным доводом и разворачивает все объявленные составляющие без прочих ключей.
- `.conventions.json` содержит раздел `deployment` со средами и составляющими; `conventions components` печатает их, а скрипт развёртывания берёт перечень оттуда.
- Манифест сборки пишется `conventions manifest`; развёртывание непомеченного коммита отказывает без названной причины.
- После установки выполняются `conventions deployed` и `conventions health`; остановленный сервис роняет шаг — проверено заведомым отказом один раз при принятии.

## Ход работы

- 2026-09-30: единственный вход — `scripts/deploy.sh --env <среда>`; среды и составляющие — раздел `deployment` в `.conventions.json` (сервер, два клиента, настройка nginx, unit systemd, nginx стенда); скрипты берут перечень `conventions components --full`; манифест — `conventions manifest` в `/opt/rbot/releases/<коммит>/manifest.json` с журналом `/opt/rbot/journal.log`; сверка — `conventions deployed` по установленным файлам; состояние — `conventions health` к самому экземпляру на `127.0.0.1:<порт>`. QA: `scripts/deploy.sh --env qa` — health UP, unknown на обоих сайтах. Проверки рабочей среды после раската — RBOT-OPS-013.
